# 岗位雷达 · Job Radar

一个供个人使用的岗位搜索与求职管理网页：自由搜索真实岗位，也能根据自己的工作经历发现适合的机会，并订阅每日邮件汇总。

> 当前状态：项目初始化，尚未完成应用开发。本文说明目标与开发约定，不表示搜索、邮件或线上服务已经可用。

## 项目目标

联网发现岗位 → 抓取原始详情 → 核验与去重 → 搜索及个人匹配 → 网页展示 → 每日邮件汇总。

### 计划功能

- **自由搜索**：按职位、技能、公司或关键词搜索，筛选地点、工作方式、经验、用工类型、薪资与发布时间；不限制固定岗位类别。
- **适合我**：根据可编辑的个人经历与技能推荐岗位，说明匹配原因和关键差距。个人匹配分不用于隐藏普通搜索结果。
- **岗位核验**：展示原始链接、来源、发布时间（如有）、首次发现及最后成功核验时间；单独说明远程地域限制。
- **求职记录**：收藏、个人备注、准备投递/已投递/面试中/已结束等状态。
- **保存搜索与订阅**：保存多个搜索条件，选择是否纳入每日邮件。
- **运行记录**：查看数据来源、检查进度、失败原因和邮件状态。

第一版不自动投递、不联系招聘方；邮件仅发往本人配置的邮箱。

## 视觉方向

暖米灰底色、黑白摄影、细线网格、克制字体、杂志式留白。保留清楚的搜索和列表结构，首屏能看到搜索框。

桌面采用左侧岗位列表、右侧详情；手机采用纵向列表与独立详情。避免大面积鲜绿、渐变、厚阴影及大量圆角卡片。参考图用于视觉理解，不复制品牌内容，不直接用整张截图做背景。

## 真实数据要求

1. 优先公司官方招聘页、能确认公司关联的ATS招聘系统及允许使用的公开接口；聚合平台用于发现线索。
2. 不生成虚假岗位，不把搜索摘要或HTTP 200当作核验通过；检查原始详情与岗位是否仍开放。
3. “原始招聘页有效”与“候选人符合地域资格”分别判断。只有remote字样不能默认允许人在中国申请。
4. 缺失薪资、日期或资格信息要明确标注，不能补造；首次发现不等于当天发布。
5. 关闭或过期与网络失败分别处理；缓存展示原核验时间。只覆盖部分来源时如实说明覆盖范围。
6. 遵守来源规则及速率限制，不绕过验证码、登录墙或访问限制。开发演示数据与真实数据隔离，不进入邮件。

## 初始个人推荐偏好

这些仅用于“适合我”的初始推荐，可以修改，不限制普通搜索：

- 中国境内可做的远程工作，可接受部分欧美时差；或南京线下/混合办公。
- 参考经历：约三年服装/纺织跟单，客户沟通、需求翻译、跨部门协调与订单推进；科技公司需求调研、方案设计与AI工具实践；网页及小程序Demo经历。
- 可探索协调、运营支持、客户成功、客户支持、行政助理、初级产品等相近机会，不设岗位白名单。
- 不虚构正式客户落地、技术资历、语言能力或高级产品经验。

个人档案与搜索条件分开保存。个人信息默认不提交至外部模型；如需使用，提供明确开关并说明发送字段。

## 每日邮件

- 每天检查一次、每天一封汇总；初始暂定北京时间08:00检查、09:00发送，可配置。
- 分“订阅搜索新增”和“适合我”两组，去重并避免重复通知。
- 仅推送符合执行框架核验与资格要求的岗位，保留原始链接和检查时间。
- 来源失败或结果不完整时明确说明，不将“抓取失败”描述成“没有新岗位”。
- 未配置邮箱与凭据时可预览，但必须标明未发送；真实邮件未经验证不能标记完成。

## 开发环境与线上运行

本仓库用于保存源代码、文档与版本记录。Codex云端开发环境用于开发和测试；网页托管、持久数据库、每日后台调度及邮件发送需要另外配置和验证。

不要将开发环境中的临时进程视为长期线上服务。正式定时任务应独立于浏览器与个人电脑运行。

技术栈暂未确定：优先复用现有项目；新项目选择易维护的前后端、SQL数据库、后台采集任务及邮件接口。选型时查阅当前官方文档，核对来源可用性、运行限制和费用。预算未确认前不启用付费服务。

## 给 Codex 的开发顺序

1. 阅读本README和两份需求文档，检查仓库、环境、网络与现有配置。
2. 验证首批数据来源，先接通至少一个真实来源，跑通搜索→详情核验→入库→去重→展示。
3. 按视觉规范实现搜索、详情、“适合我”、收藏投递及设置。
4. 扩展到2–3个真实可用来源，补齐保存搜索、任务记录和失败处理。
5. 完成每日调度与邮件预览；配置凭据后验证实际发送与防重复。
6. 验证桌面、手机及核心数据流程，更新运行说明与已知限制。
7. 具备部署条件后部署，验证关掉浏览器后任务仍能执行，并报告实际访问地址。

自行完成可逆的实现细节；缺少凭据、预算或权限时列明阻塞点，其余部分继续推进。不要只输出计划或静态演示。
